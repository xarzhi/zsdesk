## 追加：回收站仍然打开资源管理器的根因（当天修复）

- 实测：`ShellExecuteW(None,"open","::{645FF040-…}")` → 资源管理器；`ShellExecuteW(None,None,…)`（默认动词）→ ZSDesk。
  结论：**资源管理器固定用 `open` 动词打开回收站，只改类默认动词不生效**（此电脑没有这个问题，
  因为它没有 shell32 硬编码的 open 动词，默认动词才起作用）。
- 修复：回收站改为注册 `shell\open`（默认值「打开」+ Icon + `"<exe>" --recycle-bin`）并写 `shell` 默认 = `open`，
  不再用 `ZSDesk` 动词；`recycle_bin_enabled` 改为只看 `shell\open\command`。
- 新增设置 `ExplorerUi.recycle_bin_takeover`（默认 true），菜单位置 ≡ → 系统集成 →「接管桌面回收站」。
  `integration::apply/upgrade_default` 多了 `recycle: bool` 参数；关闭时 `remove_recycle_keys` 只删自己的动词，
  其余接管不动。`upgrade_default` 的“已完整接管”早退改用 `recycle_bin_complete()`（比对全部 4 个值），
  否则只写了一半的注册会被误判为已完成。
- 兼容：0.3.6 写的接管备份里含 `shell\ZSDesk` 的值/键，`validate_backup` 新增 `legacy_recycle_plan()` 白名单，
  否则老用户会看到“接管备份格式无效，未修改系统集成”而无法恢复/升级。
- 转发器兜底：`explorer_forwarder` 现在也识别回收站快照（`Snapshot.recycle`），用 `OPEN_MAGIC` +
  `ShellLocation::recycle_bin()` 转发，验证用新标签 `VERIFY_RECYCLE_BIN`（0x3452464e）；开关关闭时不转发。
- 沙箱回归测试的坑：`RegOverridePredefKey` 解除后再读 HKCU 读到的是**真实**注册表（本机装了 ZSDesk 会误判），
  必须在 override 生效期间判定；另外 shell 解析回收站会往沙箱里写 `Explorer\CLSID\{645FF040}\DefaultIcon`
  和 `BitBucket\Volume\{guid}`，所以“清理干净”只能按自有动词判定，不能要求沙箱树为空。

## 补充（14:25 之后）：双击文件夹不再先闪资源管理器

- 用户反馈：桌面双击文件夹会先弹出系统资源管理器，再由转发器关掉、打开 ZSDesk。
- 根因（与回收站同一类）：双击文件夹解析的是**字面量 open 动词**，目录类没有自己的 open，继承
  `Folder\shell\open` 的 `DelegateExecute={11dbb47c-a525-400b-9e80-a54615a090c0}`（shell32 文件夹处理器），
  所以再改 `Directory\shell` 默认动词也没用。实测：ZSDesk 未运行时 `ShellExecuteEx(..., "open", "C:\Windows")`
  一定打开 CabinetWClass。
- 修复：`integration.rs` 新增 `OPEN_VERB` / `OPEN_CLASSES`（Directory、Drive），Default 级别写入
  `shell\open`（标签“打开” + 空 `DelegateExecute` + `--shell-open "%V"`），`Folder` 类保持不动；
  备份、恢复、卸载、升级（`upgrade_default` 的早退需要 `open_verbs_owned`）全部覆盖这两组键。
- 附带 bug：`--shell-open "%V"` 打开磁盘根目录时，`"C:\"` 结尾的反斜杠被命令行当成转义引号，
  参数变成 `C:"`，窗口标题显示成一个引号。`app.rs` 新增 `repair_path_argument`（去掉结尾引号、单盘符补 `\`），
  `shell_open_target` 走同一修复，并加了单测。
- 验证：装好 release 后，ZSDesk 未运行时 ShellExecuteEx "open" 文件夹 → 直接出现 ZSDesk 窗口，
  50ms 采样 5 秒内从未出现 CabinetWClass；`C:\` 和含空格路径都正常；`--uninstall-integration` 把
  `Directory/Drive\shell\open`、类默认动词、回收站、Win+E、此电脑全部还原，再 `--integration-enable` 正常写回。

### 复核（同日）：只接管 Directory/Drive 仍不够，真正生效点是 Folder 的 command 键

- 用户复测：双击文件夹仍先开系统窗口、约两秒后被转发器关掉。实测 `HKCR\Folder\shell\open\command`
  = `C:/WINDOWS/Explorer.exe` + `DelegateExecute={11dbb47c-…}`；`HKCR\Directory\shell\open` 已被我们接管
  却未被使用 → 双击解析的是 **Folder** 类，不是 Directory。
- 更关键的坑：**注册表只按"同名同键"覆盖**。系统把 `DelegateExecute` 记在 `Folder\shell\open\command`
  上，而我们只写了 `Folder\shell\open`（verb 键）上的空串 → HKCR 合并视图仍显示 GUID，命令被忽略。
  对比验证：`Win+E` 的 DelegateExecute 本来就在 command 键上，所以空串能遮蔽，一直有效。
  正确做法：verb 键和 command 键**都写**空 `DelegateExecute`。
- 改动：`OPEN_CLASSES` 增加 `Folder`；`plan` 在 `open\command` 键补写空 `DelegateExecute`；
  新增 `open_delegate_cleared` 并纳入 `open_verbs_owned`（老安装才会被升级补写）；
  `open_verb_keys` 记录 class/shell 父键；`remove_created_key` 统一为"`Software\Classes` 下只删空键"。
- 注意：`HKCU\Software\Classes\Folder` 在用户机器上**本来就有**（Quark 网盘的
  `ShellEx\ContextMenuHandlers\  Quark.ContextMenuExt`），不能整树删，只能删空的 `Folder\shell`。
- 验证：`HKCR\Folder\shell\open\command` 的 `DelegateExecute` 变为空、命令指向 ZSDesk；
  ShellExecuteEx 打开目录仍直接进入 ZSDesk；`--uninstall-integration` 后 `Folder\shell` 干净移除、
  再 `--integration-enable` 备份记录完整（含 command 键的 DelegateExecute）。测试全绿。

### 三轮后的根因：资源管理器双击文件夹根本不读注册表

- 决定性实验：不运行 ZSDesk、也没有转发器时用 `explorer.exe <目录>` 打开文件夹 →
  资源管理器直接自己开窗口（CabinetWClass），没有任何 ZSDesk 进程被拉起。说明 **CFSFolder 的
  双击在 explorer 进程内实现**，`Folder\shell\open`（含 `command` 键上空 `DelegateExecute`）
  只对 `ShellExecute`、`Win+R`、外部程序有效，对双击无效。回收站/此电脑是 CLSID 根，走注册表，
  所以那两处一直正常。之前“改了 open 动词就能直接进 ZSDesk”的结论是错的，README/CHANGELOG 已改。
- 正确方案：`explorer_forwarder` 改为窗口事件驱动接管。
  - `SetWinEventHook(EVENT_OBJECT_CREATE..EVENT_OBJECT_SHOW)`（WINEVENT_OUTOFCONTEXT，
    独立线程 PeekMessage 泵，4ms 轮询），只认 CabinetWClass/ExploreWClass。
  - 创建事件里立刻置 `WS_EX_LAYERED` + `SetLayeredWindowAttributes(alpha=0)`：跨进程 `SW_HIDE`
    要排在 explorer 建窗之后才生效（实测可见约 60~190ms），而“全透明”在首帧之前就生效。
    实测来源窗口整个生命周期 alpha=0（肉眼不可见），ZSDesk 窗口约 0.9s 出现。
  - 主循环从 500ms 轮询改成 16ms tick + 140ms 快照扫描；隐藏窗口的候选确认 80ms。
  - 还原路径会再次触发 SHOW 事件被重新隐藏（控制面板窗口永远不出现）→ 新增 `RELEASED`
    集合，放行的窗口不再隐藏；非文件夹窗口约 700ms 原样交还并恢复 alpha=255。
- 转发器只存在于 ZSDesk 进程里：打开过一次 ZSDesk 后，即使关掉窗口宿主仍在后台接管
  （实测 status active:true、forwarded:1，来源窗口被关闭）。重启后要自动接管需要开机启动常驻，
  当前用户未开启（Run 键里没有 ZSDesk）。
- 部署：release 覆盖 `D:/Program Files\ZSDesk\ZSDesk.exe`（旧版留 `ZSDesk.exe.bak-1615`）。
  测试全绿：core 34 / ui 28 / windows 48（5 ignored）/ app 134（25 ignored）。
