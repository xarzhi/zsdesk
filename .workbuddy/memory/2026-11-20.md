## 后续修复（同日 17:20-18:05）

用户反馈「文字看不清」。用 PrintWindow 自渲染窗口 + 子窗口枚举定位到真因：
1. **`sync_file_view()` 从来没在导航后调用**（只挂在 `reload_preferences` 里），所以
   `browser.set_visible(false)` 压根没执行 —— 系统 Shell 视图（ExplorerBrowserControl/
   SHELLDLL_DefView）一直可见，盖在自绘列表上，两套文字 + 系统滚动条叠在一起。
   修：`navigation_completed()` 末尾（relayout/position_children 之后）调用 `sync_file_view()`。
2. `set_visible` 只隐藏 view 窗口不够：ExplorerBrowser 在 owner 与 view 之间还有个宿主窗口
   （带滚动条/表头）。改为先 `FindWindowExW(owner, "ExplorerBrowserControl")` 隐藏宿主，
   再沿 GetParent 链找到 owner 的最外层子窗口一起隐藏。
3. 底色浓度提高：有壁纸 0.62(浅)/0.80(深)，无壁纸 0.40/0.52。
4. 回收站条目的显示名是原始完整路径 → `folder_items::describe` 里按 `":\"` 取尾段。

### 结论（重要，别再走弯路）
窗口用 `DwmExtendFrameIntoClientArea` 铺满 + 清除为透明后，**GDI/原生子控件的文字会丢 alpha**
（ClearType 画进透明面），在 DWM 按 alpha 合成时变成彩色毛边幽灵字；D2D 自绘的文字不受影响。
所以原生 `SysTreeView32` 导航树在玻璃窗口里必然发虚，试过都没用：TVM_SETBKCOLOR/SETTEXTCOLOR、
SetWindowTheme("")、在树下面垫不透明同级 Static 窗口。真正的解法只能是**自绘导航树**。
（设置里的原生 EDIT 之所以清晰，是因为它自己 GDI 刷了不透明底色。）

### 调试手法（可复用）
`target/capture_window.py`：ctypes + PrintWindow(PW_RENDERFULLCONTENT=2) 抓窗口自身渲染，
再 PIL 存 PNG，用 ViewImage 看；`target/list_children.py` 枚举子窗口类名/可见性/矩形。
被全屏游戏挡住也能抓到，比截图靠谱。

## 第四轮：自绘列表点不开（同日 18:20-18:45）

用户报「自绘内容区点击目录进不去、点击文件不打开」。

**根因**：主窗口 `RegisterClassW` 的 `WNDCLASSW` 没设 `style: CS_DBLCLKS`，
所以窗口从来收不到 `WM_LBUTTONDBLCLK`。以前双击是 ExplorerBrowser 的 view 子窗口自己处理的，
改自绘后没人接——`WM_LBUTTONDBLCLK` 分支写了但永远不触发。
修：`wc.style = CS_DBLCLKS`（`GetClassLongPtrW(hwnd, GCL_STYLE)` 验证 0x0008）。

**兜底**：`WindowState.last_click: Option<(usize, Instant)>`，`view_click` 命中同一行且间隔
≤ `GetDoubleClickTime().max(500)` 就直接 `open_view_row`。这样慢速双击 / 远程桌面 /
SendMessage 合成输入也能打开。`sync_file_view` 与 `view_double_click` 里清空，避免索引语义变化误开。

**虚拟项目**：`open_view_row` 对没有 filesystem path 的文件补了
`ShellMenu::for_items(hwnd, &[pidl]).invoke_verb(hwnd, "open", false)`，回收站里的文件也能打开；
回收站里的文件夹走 `item_of → location_from_shell_item → Shell{parsing_name}` 已能进入（实测
`$RL5B0ZM.temp-archive`）。

### 验证手法
`SendMessageW(hwnd, WM_LBUTTONDOWN/UP)` 两次（无 DBLCLK）能测连击兜底；
`SendMessageW(WM_LBUTTONDBLCLK)` 测双击分支；tasklist 前后 diff 看文件是否真的被外部程序打开
（实测 user_config.toml 拉起 Zed.exe）。

### 遗留
自绘列表不监听文件系统变更：外部程序新建/删除文件后不会自动刷新，需要切目录或操作后重载。

## 第五轮：所有原生文本字段自绘 + 导航树黑线（同日 19:00-19:30）

用户报「搜索框文字也不清楚，你要考虑全面」。整窗材质下 GDI 写 alpha=0 → DWM 合成后是彩色毛边幽灵字，
所以四个原生 EDIT（搜索框 `search_edit`、地址栏 `address_edit`、列表行内重命名 `view_rename`、
收藏夹重命名 `rename_hwnd`）必须全部改成 D2D 自绘。

**做法**（`window/edits.rs`）：EDIT 退化为纯输入模型（保留位置/焦点/键盘/IME/剪贴板/撤销），
`SetWindowPos(edit, 1x1, SWP_NOMOVE)` 使其不再刷像素；文字/选区/光标/输入法串由 `paint_edits` 画。
- 文本区域不能再问 `GetWindowRect`（控件已是 1×1），新增 `search_area/address_area/view_rename_area/rename_area`
  四个 `LayoutRect`，统一用 `place_edit(edit, area)` 记录并放置，`sync_edit_regions()` 负责收缩/还原。
- `edit_index_at` 改成用 DirectWrite 自行测宽二分（`index_at`），不能用 `EM_CHARFROMPOS`：
  1×1 的 EDIT 会把自己的文字左滚以保持光标可见，索引会整体偏移。
- 空文本聚焦原先不画光标（只在 else 分支里画），已挪出分支；空的搜索框也能看到光标。
- 崩溃教训：`CreateRectRgn(0,0,0,0)` 空 region 和读 `EM_GETCUEBANNER` 都会 AV（msvcrt），
  1×1 + 缓存 cue 文案是稳定的。

**导航树右边缘黑线**（`nav_tree.rs`）：分隔线取 `palette.divider`（浅色是纯黑）却把 alpha 硬写成 `0xFF`
→ 壁纸下就是一条硬黑竖线。改成用调色板自带 alpha（约 8%）。顺带把滚动条滑块从
`text_secondary@40%`（浅色≈纯黑 40%）改成中性半透明灰（浅 15% / 深 20%），内收 1px。

**验证**：`ImageGrab` 抓窗口 bbox 取像素值对比（黑线处由 (0,0,0) 变成与环境一致），
`GetGUIThreadInfo` 看 `hwndFocus` 确认点击确实把焦点给了 ID_SEARCH。
注意窗口 bbox 含 DWM 不可见边框，最右 8px 会抓到桌面其它程序。

## 第六轮：启动白屏 / 顶栏透明 / 壁纸发白（同日 19:20-20:00）

用户三问：①打开时白屏好几秒 ②tab、地址栏、搜索栏白底要改成透明+一点黑 ③壁纸 100% 仍发白。

**白屏根因**：整客户区 `DwmExtendFrameIntoClientArea` 后，程序首帧之前客户区是 DWM 的
「玻璃底色」＝浅色主题下纯白。原顺序是 ShowWindow → 等 `WM_PAINT`，中间实测 70–100ms。
- 试过 1：`InvalidateRect + UpdateWindow`（隐藏窗口）→ 无效，Windows 不给不可见窗口发 WM_PAINT。
- 试过 2：隐藏时 `GetDC + BitBlt` 画进表面 → 无效，blit 被丢弃（没有重定向表面）。
- **有效做法**：`DwmSetWindowAttribute(hwnd, DWMWA_CLOAK=13, 1)` → ShowWindow → `UpdateWindow`
（此时窗口已可见但 DWM 不合成，WM_PAINT 真的会到）→ 解除 cloak。首帧即成品。
- 另：cloak 期间那次 WM_PAINT 的 `ps.rcPaint` 可能为空，此时按整幅表面 blit。

**发白根因**：`paint_backdrop` 固定叠 `palette.layer`（浅色≈#F9F9F9）58%/74% 当可读性白纱，
100% 不透明度也照叠。改为自适应：
- `gfx.wallpaper()` 返回 `(IWICBitmapSource, mean)`，mean 是解码后（含 blur/dim）画面的
  BT.709 平均亮度，`WallpaperLayer` 记住它。
- `paint_backdrop`：`effective = mean*opacity + behind*(1-opacity)`，浅色目标 0.42（≈9:1），
  深色 0.20（≈4.2:1）；够了不叠，不够才补，上限 0.72。亮壁纸=完全不动。

**白底组件**：`zsdesk_ui::theme::Palette::veil(alpha)` 统一返回 `rgba(0,0,0,a)`（深色也用黑，
因为深色白字需要压暗而不是提亮）。替换处：paint_strip(0.05)、active tab(0.09)/hover(0.05)、
`text_box`(7/9/11%)、`paint_chrome_layer`(0.06)、状态栏(0.05)、nav_tree 底(0.06)、
search_panel 外壳(0.06)。输入框描边：浅色 `veil(0.16)`，深色 `rgba(255,255,255,0x26)`。

**坑**：`cargo build -p zsdesk-app` 默认是 full 版（`themed` feature 关闭），
`apply_theme` 里 `scheme = if THEMED {...} else { System }`，所以直接改配置的 color_scheme
在 full 版里被忽略。验证深色必须 `--features themed`，且配置目录变成 `%APPDATA%\ZSDesk-Theme`。

  长名字不会压到滑块下面。
- `max_scroll_in(height, dpi)` 与 `max_scroll(dpi)` 分开：滚动条/拖动按**当前绘制高度**算，
  不能让缓存的 `self.height` 和传入 rect 不一致时算出错的 max。
- `custom_view`：`view_click` 的 ScrollBar 分支 SetCapture 并清 `last_click`（避免和上一行的
  双击配对）；`view_drag_bar`、`end_view_drag_bar`；`view_hover` 维护 `bar_hot`。
- `input.rs`：`mouse_move` 里拖动优先于其他悬停；`mouse_up` 先结束拖动；
  `mod.rs` 的 `WM_MOUSELEAVE`/`WM_CANCELMODE`/`WM_CAPTURECHANGED` 都要清掉拖动与高亮。

**隐藏 bug**：拖动后首行常是半行，行文字直接画到列标题上（以前滚轮是整行 72px 的倍数，
永远不会出现半行）。修法：行区域再 push 一层 `body` 裁剪（D2D 的 clip 可以嵌套）。

**调试经验**：模拟鼠标点击时窗口如果没在前台，第一次点击会被激活流程吃掉，
先点一行（能看到选中高亮＝输入链路通）再拖；`GetWindowRect` 比 DWM 的
EXTENDED_FRAME_BOUNDS 每边大 7px，所以可见内容不会和 8px 的缩放边框重叠，
滑块贴到客户区右边缘也是可以拖的，不需要额外内缩。

## 第九轮：一键打包 setup（同日 22:20-22:45）

**产物**：`releases\0.3.6\ZSDesk-0.3.6-x64-setup.exe`（3.8 MB）。新脚本仓库根 `package.ps1`
+ 新建 `packaging/windows/setup.iss`（纯 ASCII）。用法 `.\package.ps1 0.1.0`，不带参数取
Cargo.toml 版本。

**版本号注入**：脚本临时把版本写进 `Cargo.toml` 的 `[workspace.package] version` 与
`crates/zsdesk-app/resources/zsdesk.rc`（FILEVERSION/PRODUCTVERSION 四段 + FileVersion/
ProductVersion 字符串），编译后 finally 还原三个文件（含 Cargo.lock），再用 cargo metadata
把锁文件同步回去。核对点：`--build-info` 的 version 与 exe 的 VersionInfo.ProductVersion
都必须等于请求版本。

**踩过的三个坑**：
1. `.ps1` 带中文存成 UTF-8 无 BOM 时，Windows PowerShell 5.1 按 GBK 解析，报「表达式或语句
   中包含意外的标记」。必须写 BOM（`New-Object Text.UTF8Encoding($true)`）。
2. `& $exe --build-info | ConvertFrom-Json` 在 PS 5.1 下按 OEM 码页解码子进程输出，
   `"edition_name":"全量版"` 变乱码 → JSON 解析失败。改用 ProcessStartInfo +
   StandardOutputEncoding=UTF8。
3. 正则替换写 `"FILEVERSION`$1$quad"` 会拼成 `$10,1,0,0`（$1 后接数字当成 $10）→ RC.EXE 报
   `unrecognized VERSIONINFO field`。必须用 `${1}`。
另：.iss 保持纯 ASCII，中文界面交给 `compiler:Languages\ChineseSimplified.isl`，避免 ISCC 按
ANSI 读源文件出乱码。
