## 第十轮：文件拖出 / 拖入

**诉求**：「把文件向外拖动，还有把外面的文件拖进程序里都有问题。向外拖动的功能根本没有写，
其他文件拖进来鼠标是禁用的状态，不可拖进」。

### 向外拖（新增）

- 新文件 `crates/zsdesk-windows/src/ole/drag.rs`：`#[implement(IDropSource)] struct Source`
  + `begin(owner, pidls, allowed) -> Result<DROPEFFECT>`，内部
  `items_ui_object(owner, pidls)` 造数据对象、`DoDragDrop` 起拖。
  `QueryContinueDrag`：Esc → `DRAGDROP_S_CANCEL`；三个鼠标键都松了 → `DRAGDROP_S_DROP`；
  否则 `S_OK` 继续。`GiveFeedback` 一律 `DRAGDROP_S_USEDEFAULTCURSORS`（光标和缩略图交给系统）。
- **坑：DoDragDrop 是模态循环**，会重入窗口过程；不能在 `WindowState` 借用期间调用。
  解法：`input.rs::begin_view_drag` 越过 `SM_CXDRAG/CYDRAG` 阈值后 `ReleaseCapture`+
  `PostMessageW(WM_BEGIN_DRAG, Box<Vec<Vec<u8>>>)`，窗口过程**在借 state 之前**处理这条消息。
- 拖动结束拿到 `DROPEFFECT_MOVE` 就 post `ACTION_AFTER_DRAG` 重读目录，否则列表留着已移走的行。

### 向内拖（补落点）

- `DropZones` 增加 `browser` / `tree`；`ChromeDrop::zone` 把这两块当 `DropZone::Files`。
  以前只有收藏栏、标签栏两个落点，文件拖到列表上自然是「禁止」光标。
- `ChromeDrop::effect`：Alt(`GetKeyState(VK_MENU)`)→LINK、Ctrl→COPY、Shift→MOVE、
  跨卷→COPY、否则 MOVE。（`MODIFIERKEYS_FLAGS` 里没有 Alt，必须直接读键状态。）
- `custom_view.rs` 新增 `drop_folder` / `drop_row` / `drop_files` / `drop_highlight`：
  落点是文件夹行或导航树行就进那个目录，否则进当前目录；`all_inside` 判定「拖回原目录」直接返回，
  避免 Shell 弹覆盖自己的框。
- `file_view.rs` / `nav_tree.rs` 增加 `drop_target` 与描边绘制：淡 accent 填充 0x2e +
  0xaf 描边，`set_drop_target` 返回是否真的变了才重绘。

## 第十一轮：内容区缩略图 / 每文件图标

**诉求**：「内容区域文件的缩略图显示的不对，图片、视频要显示相应的缩略图。其他文件，
exe、程序文件之类的要显示图标」。

### 原因

`FolderEntry.icon` 是 `SHGetFileInfoW(..., SHGFI_SYSICONINDEX | SHGFI_USEFILEATTRIBUTES)`
按**扩展名**查出来的系统图像列表下标（`icon_index_for_name`，为了列目录快、不碰磁盘）。
所以同扩展名的文件长得完全一样：所有 exe = 通用程序图标，所有 png = 带 PNG 字样的占位图。
自绘列表只用 `system_icon(index, px)` 取图标，从来没走过缩略图通道。

### 改法

- `shell/icons.rs` 里那个 `IconLoader`（后台 STA + `IShellItemImageFactory` + 窗口消息回投，
  原先给桌面围栏写的、当时无人使用）正好是缺的那块，接起来：
  - `IconRequest` 增加 `path: Option<PathBuf>` 和 `for_path()`：UI 线程只给路径，由工作线程
    `item_from_parsing_name` 生成 Shell item（避免每行一次跨进程调用）。
  - 新增 `wants_thumbnail(name)`：图片/视频扩展名白名单，决定 `SIIGBF_RESIZETOFIT`（缩略图）
    还是 `SIIGBF_ICONONLY`（文件自己的图标）。
- `window/mod.rs`：`WM_VIEW_IMAGES = WM_APP + 54`、`images: Option<IconLoader>`、
  `view_images: HashMap<String, paint::IconEntry>`、`view_images_wanted: HashSet<String>`；
  `create()` 里 `IconLoader::spawn(hwnd, WM_VIEW_IMAGES)`，`handle()` 分支调
  `apply_view_images(wp.0)`（先 `accepts_notification(token)` 校验）。
- `window/custom_view.rs`：`prepare_view_icons` 改成「有路径的文件先问 `view_image`，
  没到货就用系统图标兜底」；`view_image` 负责 cache key（`t|i` + px + path）、首次排队、
  上传缓存（generation 校验，同 `item_icon` 的写法）；`apply_view_images` 把 HBITMAP 用
  `gfx.wic_from_hbitmap(bitmap, alpha)` 转成 WIC 再缓存。
- 列表先画系统图标 → 缩略图到货后替换，所以不会有空行，也不会卡在解码上。

### 两个容易踩的点

1. `WM_VIEW_IMAGES` 在 state 被借用时到达会走进 `reentrant()` 的 `_ => DefWindowProcW`，
   通知就**丢了**（loader 只在 `ready` 为空时 post，丢了就一直不投）。已加入 reentrant 的
   延迟列表。
2. 缓存超 512 条清空时，必须连 `view_images_wanted` 一起清，否则被清掉的 key 记着「已请求」，
   那几行从此永远只有兜底图标。

### 验证

- `thumbtest`（gif/png/mp4/exe/txt）：gif、png、mp4 显示真实画面，app.exe 显示 ZSDesk 图标、
  notepad.exe 显示记事本图标（两者不再相同），txt 保持文本图标。
- `D:/Program Files\winc`：OpenConsole.exe / uninstall.exe / winc.exe 各自不同；
  「winc.exe - 快捷方式」显示目标程序的图标（**没有**快捷方式小箭头——`GetImage` 不合成
  overlay，真要补得走 `SHGFI_LINKOVERLAY` + `IImageList::Overlay`）。
- `C:/Windows/System32`（4939 项）：滚到底、按 End 跳末尾，图标齐全无空白，无明显卡顿。
- `C:/Users/22357/Pictures`：每张截图/二维码都是真实缩略图。
- `cargo test --release -p zsdesk-windows -p zsdesk-app`：138 + 57 通过；新增
  `only_pictures_and_videos_ask_for_a_thumbnail`。

### 补：缩略图被拉成正方形（第三处坑）

Shell 的 `IShellItemImageFactory::GetImage(RESIZETOFIT)` 返回的是**保持原比例**的位图
（实测：400×100 的图给 `16x4`，100×300 的给 `6x16`），而 `Canvas::image` → `DrawBitmap(bitmap, rect)`
会按 rect 拉伸。所以 16:9 视频被压成方块、长条图被压扁。
改法：`file_view::fitted(rect, bitmap)` 用 `ID2D1Bitmap::GetSize()` 取真实像素比，
按比例缩放到图标格内并居中；方图结果与原来一致。
验证：`target/aspect/{wide,tall}.png` 现在显示为扁条 / 竖条，内容不变形。

## 第十二轮：排序 / 查看菜单真的生效

**诉求**：「地址栏下面的菜单栏，排序和查看里面的功能全都没有用」。

### 原因

两个菜单执行的都是 Shell 视图的命令（`IFolderView2::SetSortColumns` /
`SetViewModeAndIconSize`）。默认 `custom_view: true`，屏幕上的行是 ZSDesk 自绘的，
Shell 视图被 `set_visible(false)` 藏着，所以命令「成功」但一行都不会动。

### 改法

- `file_view.rs` 新增 `Layout`：`Details` / `Listing` / `Content` /
  `Icons { icon, lines }`，`from_id` 与 `menus::VIEW_CHOICES` 一一对应，`id()` 反查供菜单打勾。
  几何统一走 `cells(rect, dpi)`（单元格宽高、列数、表头高），`cell_rect` 按索引算位置。
  网格布局**总是**扣掉滚动条 lane 的 14 DIP，列数不会因为滚动条出现而抖动。
- 绘制分两路：`paint`（详细信息，原逻辑）与 `paint_cells`（图标/列表/内容）。
  平铺与内容各有两行文字；选择块、拖放描边、空目录提示都按单元格画。
- `SortKey` 增加 `Created`；`sort_by(key, ascending)` 精确指定方向，`set_sort` 保留「同键翻转」。
  `apply_sort` 先按名字记住选择再重排，排序不会清空选中。
- `FolderEntry` 增加 `created`；`list(location, include_hidden)` 把系统的
  「隐藏的项目」开关（`folder_settings()`）传进目录扫描，虚拟目录结果同样过滤。
- `menus`：`view_menu_current(id, show)` 直接按布局 id 打勾；`sort_menu(..., groupable)`
  在自绘模式下把「分组依据」置灰（列表还没有组标题行）。
- 接线的入口全部改走 `choose_view(id)`：查看菜单、`Ctrl+Shift+1..8` 预设、
  `Ctrl+±` 缩放、`Ctrl+0`、状态栏两个视图按钮（`view_toggles` 不再对自绘关闭）。

### 踩到的坑

1. `row_rect` 原来接受「已扣 lane 的 content rect」，改成 `cell_rect` 后内部会再扣一次，
   列表右侧会少一条。统一改成传**面板 rect**（`view_rect()`），内部自己算 content。
2. 网格下 `step()` 一「行」是一排单元格，要乘列数；Page 键用 `page_rows()`。
3. 图标要按布局请求像素（96 DIP → 96 px），否则大图标是 16 px 放大后的糊块。
   为此 `view_image` / `item_icon_size` 都接受 px，缓存 key 已含 px。
4. 菜单里 Down 键的起点是「第一项已经带焦点框」，所以 N 次 Down = 第 N+1 项；
   测试脚本里数错了几次（把「分组依据」当成「递减」）。

### 验证

- 查看八种模式逐一截图：超大/大/中/小图标、列表、详细信息、平铺（第二行「GIF 文件 618.4 KB」）、
  内容（图标左、两行右）。菜单对勾与状态栏按钮高亮随布局变化。
- 排序：大小升序 6 B→24.3 MB、降序反向、表头箭头 `↑/↓`、同键再点翻转。
- 隐藏的项目：`attrib +h` 造一个文件，开关打开时出现（7 项）、关闭后消失（6 项）。
- `Ctrl+Shift+2`、状态栏「大图标」按钮都能切换布局。
- 新增 5 个单测（视图 id 往返、网格每格中心命中自身、切换布局保留选择、创建日期排序、
  `sort_by` 方向），`cargo test --release -p zsdesk-windows -p zsdesk-app -p zsdesk-ui`：143+29+57 通过。

# 第十三轮：此电脑设备卡片 + 导航窗格对齐资源管理器

用户要求：① 打开「此电脑」右侧不要文件列表，要像原生一样显示盘符和容量条；
② 盘符从 C 开始往后排；③ 左侧目录树和系统资源管理器同步（常用系统目录 + 快速访问固定项）。

## 关键结论

- **快速访问的正确数据源**：`shell:::{679F85CB-0220-4080-B29B-5540CC05AAB6}` 命名空间
  `BindToHandler(BHID_EnumItems)` 只返回「固定的文件夹」（9 项，正好是用户截图里那 9 个），
  不含最近使用的文件。在资源管理器里钉住/取消文件夹，这里跟着变。
  图库 `shell:::{e88865ea-0e1c-4e20-9aa6-edcd0212c87c}` 也存在（本机 38 张图）。
  网络用 CLSID `::{F02C1A0D-…}`（`FOLDERID_NetworkFolder` 的 known-folder 路径取不到）。
- **盘符信息**：`GetDriveTypeW` + `GetDiskFreeSpaceExW`；`GetDiskFreeSpaceExW` 的第 2 个参数
  才是「可用空间」（第 4 个是卷的空闲总量）。未就绪设备两个 API 都失败，但盘符和类型仍在。
- **数字格式**：资源管理器是「三位有效数字 + 截断」——1.8198 TB → 1.81 TB，465.99 → 465，
  64.63 → 64.6。用 `10^decimals` 乘再 `floor`，不能用 `{:.1}` 四舍五入。
- **驱动器图标**：`SHGetFileInfoW(path, 0, SHGFI_SYSICONINDEX)`（不带 `SHGFI_USEFILEATTRIBUTES`），
  对 `C:/` 返回硬盘图标、U 盘返回可移动盘图标。`icon_index_for_name` 只会给文件夹图标。
- **此电脑是隐藏项**：Shell 把未就绪的驱动器标成 hidden，`include_hidden=false` 会把它滤掉，
  原生却照样显示 U 盘 (F:)。→ 此电脑这一层不过滤 hidden。

## 实现

- 新增 `crates/zsdesk-windows/src/shell/drives.rs`：`Drive { letter, kind, total, free }`、
  `Drive::of_root`、`short_size`、`DriveKind::label`。
- `FolderEntry` 加 `drive: Option<Drive>`；`list()` 对 ThisPc 走 `sort_drives`（字母序）；
  `describe()` 对盘根用 `icon_index_for_path`；`FolderEntry::file_name()` 对盘返回 `D:/`
  （`IShellFolder::ParseDisplayName` 只认这个，显示名「本地磁盘 (D:)」解析不了，
  否则右键菜单会退化成背景菜单）。
- `folder_items::tree_roots()` 返回 `TreeRow { name, location: Option<…>, icon }`，
  `None` = 分隔行；结构：主文件夹 / 图库 / ─ / 快速访问固定项 / ─ / 此电脑 / 网络。
- `nav_tree::NavRow` 加 `separator`，`location` 变 `Option`；分隔行画 1px 线、不可点、
  方向键跳过；`ensure_loaded` 后自动展开「此电脑」。
- `file_view`：`is_devices()`、`icon_px()`、`cells()` 返回卡片网格（236×74 DIP、表头 46）、
  `content_rect` 留 8 DIP 边距、`hit` 扣 header、`paint_devices()` 画分组标题＋图标＋名称＋
  容量条（末段留 2px 间隙）＋「可用/共」；`sort_items` 对带 `drive` 的条目永远按盘符排。
- 菜单：`view_menu_with(…, choices)` / `sort_menu_with(…, sortable)`，此电脑下 8 个视图项
  与排序项全部置灰、不打勾；`choose_view` 直接返回。

## 踩到的坑

1. 先按名字排序会把「Lenovo (G:)」排到「本地磁盘 (C:)」前面 —— 盘符视图一律按字母。
2. `folder_children` 内部又 filter 了一遍 `!hidden`，导致树里少一个 U 盘 (F:)。
3. 模拟点击坐标算错（窗口是无边框自绘，客户区原点 = 窗口左上 + (8,0)，没有标题栏偏移），
   一度以为卡片命中错位；最后用临时 `writeln!` 打出 `view_rect`/`content_rect` 才对齐。
4. 启动进程要用 `exec ./ZSDesk.exe` 作为后台任务，`cmd & sleep` 会在脚本结束时被回收。

## 验证

- 「此电脑」5 张卡片 C/D/E/F/G，容量 64.6 GB / 465 GB、98.6 / 465、329 GB / 1.81 TB、
  U 盘「可移动磁盘（未就绪）」、186 / 931；窄窗口自动变 2 列。
- 双击 C 卡片进 C:/；右键 D 卡片出完整盘符菜单（打开、固定到快速访问、格式化为、属性…）。
- 树的 9 个快速访问项与资源管理器截图逐项一致，分隔线与图标正确；点 preMusic/music 正常导航。
- 深色主题下容量条、文字、分隔线均清晰。
- `cargo test --release -p zsdesk-windows -p zsdesk-app -p zsdesk-ui`：145 + 30 + 62 通过。

## 搜索框白色背景（17:05）
- 需求：把搜索框那块白色背景变透明。
- 排查关键：`SetWindowRgn` 的空区域**挡不住 EDIT 自己擦背景**。
  实测（探针在 edit_proc 里读 DC 裁剪与窗口区域）：
  `rgn=1 rgnbox=0,0,0,0`（窗口区域确实是空的）但 `clipkind=2 clip=-886,-76,282,683`（DC 裁剪框
  仍然覆盖整块输入区），随后 EDIT 照样收到 WM_ERASEBKGND(0x14)/WM_PAINT(0xf) 并画出
  `COLOR_WINDOW` 白底。所以「区域设空 → 不画」这个假设是错的。
  另一个坑：白色是**残留像素**，父窗口只在 rcPaint 范围内 BitBlt，而子窗口的窗口矩形会裁剪
  父窗口的绘制，所以白块会一直留在屏幕上，直到有人显式让父窗口重绘那块区域。
- 修法：
  - `edits.rs`：`HOLLOW_FIELD` 窗口属性 + `field_hollow()`；材质下给每个输入框打标记（空区域
    保留，作用是让点击落到窗口自己身上），经典材质下移除标记并还原区域。
  - `mod.rs::edit_proc`：命中 hollow 时 `WM_ERASEBKGND` 返回 1、`WM_PAINT`/`WM_PRINTCLIENT`
    只 BeginPaint/EndPaint 校验，一律不画。
  - 从经典切到材质时 `invalidate()` 一次，清掉控件之前已经画上去的底色。
- 验证：隔离配置（亚克力 + 壁纸）+ 部署版 release，搜索框内 886..1121/76..94 的纯白
  `(255,255,255)` 变成背景色 `(192,158,134)`；点击后输入 alpha，文字/光标/蓝色焦点线正常。
- 新增单测 `a_material_marks_the_text_fields_hollow_and_classic_undoes_it`。测试 157/22/30/62 全绿。
- 部署：备份 `ZSDesk.exe.bak-1707-searchbg`，kill 33728，explorer 拉起新版 PID 32040。
- 教训：**「设个空区域它就不画了」必须实测**。要判断一个控件到底画没画，就在它的子类里
  同时打印窗口区域和 DC 裁剪框，再截屏取像素，三者对照。
