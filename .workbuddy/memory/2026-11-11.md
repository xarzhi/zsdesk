## 21:50 材质铺满整窗：导航窗格半透明，文件列表做不到

- 关键误解修正：以前 `relayout` 里 `extend_frame(hwnd, layout.browser.y)` 只把 DWM 边框扩展到
  命令栏下方 → 客户区下部根本不在扩展边框内，材质“只有上半截”。改成 `if material { 客户区高度 }`。
- 导航窗格：Shell 的 `NamespaceTreeControl`/`SysTreeView32` 背景是我们用 `TVM_SETBKCOLOR` 设的
  白色，控件本身没有 alpha → 只能给**承载窗口**加 `WS_EX_LAYERED` +
  `SetLayeredWindowAttributes(LWA_ALPHA)`。新函数 `theme::set_surface_translucency(hwnd, Option<u8>)`
  （None 时去分层并复位 alpha 255），`NamespaceTreeHost::set_translucent`，`WindowState::PANE_ALPHA = 205`，
  `apply_pane_material()` 在 apply_theme / 建树后 / navigation_completed / toggle_fullscreen 调用。
  实测：亚克力下导航窗格像素 (245,235,244)（壁纸色透出来），经典下 255 → 生效。
- `paint_content` 在有材质时 `clear_rect` 而不是铺 `p.content`，分隔条缝隙也透材质。
- **文件列表（右侧）做不到**：Win11 是 `SHELLDLL_DefView` → `DirectUIHWND` 项目视图。
  实测结论（都试过）：
  1. `SetLayeredWindowAttributes` 给 `SHELLDLL_DefView` 能成功（ex-style 变成 0x80000），但列表一点不淡
     → DUI 内容不在父窗口的重定向表面里；
  2. 给 `DirectUIHWND` 自己设 `WS_EX_LAYERED`：**跨进程和进程内都失败**（ex-style 前后都是 0x0，
     GetLastError=87）。所以“整体半透明”这条路对列表无效；
  3. `IFolderView2::SetCurrentFolderFlags(FWF_TRANSPARENT/ FWF_DESKTOP)`：无任何变化；
  4. 网上唯一可行方案是像 ExplorerBlurMica 那样注入 dui70 钩
     `DirectUI::Element_PaintBackground`——不在本程序范围内。
  → 最终保持系统白/深色底，与资源管理器一致；README/CHANGELOG 已写明原因。
- 其它：`ExplorerBrowserHost::view_window()` 已存在（commands.rs 里），别重复加（E0592）。
  实测踩坑：调试包 `target/debug/zsdesk-app.exe` 和已安装版共用 profile，单实例机制会让新进程
  直接转发给正在运行的实例 → 截图截到的是旧版本窗口。**探测前先结束全部 ZSDesk 进程**。

## 22:40 系统视图（导航树 / 文件列表）透材质：四种办法全部实测失败

用户要“导航树和文件列表也透出亚克力”，逐项真机验证（23H2 / 22631）：

1. **树宿主加 `WS_EX_LAYERED` + `LWA_ALPHA 205`**（上一版实现）：白底仍在（树自己画），
   而且整个窗口一起淡 → 文字发灰，用户报“文字看不清”。**此方案已撤销**。
2. **跳过 WM_ERASEBKGND**（子类化树与宿主，返回 1）：树收到 WM_PAINT 后仍填白。
3. **`SetWindowTheme(view, L"", L"")` + `TVM_SETBKCOLOR(CLR_NONE)` + 关 `TVS_EX_DOUBLEBUFFER`**：
   程序内 `GetWindowTheme` 返回 0（主题确实没了）、`TVM_GETBKCOLOR` 读回 `0xFFFFFFFF`
   （CLR_NONE 生效），**区域仍纯白** → `SysTreeView32` 无条件填背景，CLR_NONE 语义在 Win11 不成立。
   白不是宿主画的（宿主 WM_PAINT 已跳过；隐藏树后区域立刻透出壁纸）。
4. **颜色键分层 `LWA_COLORKEY(白)`**：**背景真的透明了**（像素 255 → 壁纸色 169,211,127），
   但 layered 窗口吞掉鼠标点击——点击前后 `TVM_GETNEXTITEM(TVGN_CARET)` 不变、不导航；
   去掉 colorkey 立刻恢复。**不可用**。
5. 文件列表：`DirectUIHWND` 拒绝 `WS_EX_LAYERED`（ex-style 前后 0x0、`SetLayeredWindowAttributes` 失败），
   `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)` 返回 0，
   `FWF_TRANSPARENT/FWF_DESKTOP` 无效。

**结论**：这两块只能保持系统不透明底色（与资源管理器一致）；要透明只有自绘视图一条路。
别重复试这些 API。

其它踩坑：
- `TVM_*` 从 `0x1100` 起（`TVM_GETBKCOLOR=0x111F`）；`0x1000` 是 `LVM_*`，外部探测读错值很容易误判。
- 主窗口去掉 `WS_CLIPCHILDREN` 后 D2D 整窗 Clear，能让未被子窗口覆盖处透材质，但整帧会覆盖子窗口
  内容、闪烁风险大，已回退。
- 探测进程必须由同一段脚本 `subprocess.Popen` 启动：工具命令结束时其子进程会被清理，跨命令留下的
  实例看起来像“程序崩溃退出”。
