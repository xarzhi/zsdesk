## 12:20 设置里的分段按钮组左边没内边距
- 用户反馈：设置对话框里「颜色模式 / 窗口材质」这种分段按钮组，最左边贴着边框没有内边距。
- 根因（`crates/zsdesk-app/src/settings/model.rs::control_boxes` 的 `Control::Segments`）：
  `total = 各段宽度之和 + 4`，但选项矩形从 `right - total` 开始排，且每段宽度自己减了 2：
  → 左内边距 0，段间空隙 2，右端多出 6。空隙全被推到了右边。
- 修法：引入 `inset = s(2.0)`（四边统一），`total = sum + inset*2`，选项从 `left + inset` 开始、
  宽度不再缩减（相邻选项靠各自 1px 的绘制内缩形成 2px 间隔）。视觉上离边框 3px，和上下一致。
- 回归测试 `a_segmented_control_pads_both_ends_equally`：遍历所有页面，断言左 > 0、左右相等、
  且与上下内边距一致（16 个设置测试全绿）。
- 验证踩坑：用 ctypes 点主窗口右上角齿轮要**先量出图标的真实像素列**（我在截图里量到图标簇
  948-961 / 997-1008，y 8..21，齿轮是第二簇），之前凭视觉模型给的坐标点偏了，一直点不开设置。
- 用户当前跑的是 `target\release\zsdesk-app.exe`（不是 `D://Program Files\ZSDesk\ZSDesk.exe`），

## 21:40 重命名框两个光标（一个闪一个不闪）
- 现象：白框里左边一根在闪、右边一根不动。左边是**系统 caret**（空心 EDIT 仍有，系统直接画屏幕，
  不受 1px 窗口和空 region 限制），右边是自绘 caret。
- 自绘不闪的根因：重命名框在 action 回调里 `SetFocus`，此时窗口状态被借用，EDIT 发的 `WM_COMMAND(EN_SETFOCUS)`
  重入后被 `reentrant()` 丢给 `DefWindowProc` → 光标定时器从未 SetTimer。解法：子类在
  `WM_SETFOCUS/WM_KILLFOCUS` 补发自定义 `WM_EDIT_FOCUS`（`WM_APP+55`，加进 defer 列表），
  由 `edit_focus_changed()` 启停 `TIMER_CARET`。
- 定时器 ID 撞车：`TIMER_CARET` 原来是 12，和 `TIMER_NAV_REFRESH` 一样 → 互相 KillTimer。改成 13，测试 `every_timer_uses_its_own_id`。
- 系统 caret 用 `HideCaret`+`DestroyCaret` 在子类里干掉（仅空心字段、且焦点在该字段时）。`DestroyCaret` 只对当前线程有效，够用。
- 更深的坑：`sync_edit_regions` 开头 `if material && edits_hollow { return }`，而 `edits_hollow` 是「窗口状态」不是「控件状态」；
  重命名框懒创建时窗口早已材质化 → 从未 SetPropW(HOLLOW_FIELD)/空 region，只被挤成 1px。改成逐控件判断。
  测试 `a_field_created_after_the_material_is_hollowed_out_as_well`。
- 验证：`GetGUIThreadInfo` 看 `hwndCaret` 恒为 None；连拍 10 帧数框内深色像素 1398/1415 交替（差 17 = 一根 caret）。
